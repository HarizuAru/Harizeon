# AGENTS.md — Harizeon

Guidance for AI coding agents working in this repo.

## Source of truth

`harizeon-master-plan.txt` (repo root). Sections 05–11 are the build spec.
Build only the current milestone in the §16 roadmap; do not scope-creep into
later services (Vault, Watch, Shield, Guard, Respond are v0.2+).

## Stack & conventions

- **Web/console:** Next.js 16 (App Router) + TypeScript (strict) + Tailwind v4.
  - Next 16 has breaking changes vs. older versions. Before editing web code,
    read the bundled docs at `web/node_modules/next/dist/docs/` and heed
    `web/AGENTS.md`.
  - Turbopack is the default bundler; `next lint` is removed — use
    `npm run lint` (ESLint flat config). `next build` typechecks but does not lint.
  - Async request APIs: `params`, `searchParams`, `cookies()`, `headers()` are
    Promises — `await` them.
  - `LayoutProps<'/...'>` / `PageProps<'/...'>` are global helpers generated by
    the build; no import needed.
- **UI is pure black & white (§10).** The default Tailwind colour palette is
  intentionally cleared in `web/src/app/globals.css` (`--color-*: initial`).
  Do not reintroduce colour. Encode severity with `SeverityChip` markers, type
  weight, and borders. Data/IDs/timestamps are monospace; prose is sans; corners
  are sharp (radius 0).
- **Database:** schema lives in `db/migrations/*.sql` (§07). Add new work as
  `NNNN_name.sql`; never edit an already-applied migration. Row-level security
  keys on the `harizeon.org_id` GUC — the app must set it per request and
  connect as a **non-owner** role (the owner bypasses RLS and is for migrations).

## Verify before finishing

- `cd web && npm run build`
- `cd web && npm run lint`
- Migrations: `docker compose up` applies them; CI validates against Postgres 16.

## Hard rules

- No active scanning of an asset without verified ownership (§12). No bypass.
- No secrets in the repo. `.env` is gitignored; copy from `.env.example`.
- Do not commit or push unless explicitly asked.
