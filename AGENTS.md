## 2. Repository Topology & Plane Boundaries (§06.1)

| Directory | Plane / Role | Allowed Access | Forbidden |
| :--- | :--- | :--- | :--- |
| `web/` | Console UI (Next.js 16) | Calls Fastify API only | Direct DB access, Redis access, or scanner execution |
| `api/` | Control Plane (Fastify) | Postgres (non-owner RLS role), Redis Streams (`api/src/lib/queue.ts`) | Running active network scans inside HTTP handlers or `buildServer()` |
| `worker/` | Data Plane (Python) | Redis Streams + job payload only | **Any DB credentials, `DATABASE_URL`, SQL drivers, or direct asset creation** |
| `db/` | Schema & Migrations (§07) | Sequential `db/migrations/NNNN_name.sql` | Editing or deleting any already-applied migration |

### Cross-Plane & Control-Plane Invariants
- **Queue seam:** All control-to-data plane communication crosses strictly through `api/src/lib/queue.ts` (`ScanQueue`).
- **Deterministic server boot:** Start background loops (`ingest`, `reaper`, `recheck`) exclusively inside `start()`, **never** inside `buildServer()`, so integration tests remain deterministic.
- **Discovery validation:** `worker/` emits discovered hosts via the `discovered` queue event. `api/` must validate that every discovered host is a **strict subdomain** of the verified scanned asset before inserting an asset record.
- **Ownership gate (§12):** Never trigger or enqueue an active scan without verified asset ownership. Zero bypasses, debug flags, or skip-verification paths.

## 3. Stack & Engineering Rules

### Web / Console (`web/`)
- **Stack:** Next.js 16 (App Router), TypeScript (`strict: true`), Tailwind CSS v4, Turbopack (default).
- **Async Request APIs:** `params`, `searchParams`, `cookies()`, and `headers()` are `Promise`s — always `await` them.
- **Generated Route Types:** Use global `LayoutProps<'/...'>` and `PageProps<'/...'>` helpers generated by Next.js; do not manually import them.
- **Linting vs. Building:** `next lint` is removed in Next 16 — run `npm run lint` (ESLint flat config). `next build` typechecks but does **not** lint.

### UI & Design System Lock (§10 — Overrides Generic UI Skills)
- **Pure monochrome only:** `web/src/app/globals.css` intentionally clears the Tailwind color palette (`--color-*: initial`). **Never** add colors, gradients, colored badges, or external UI themes (even if generic frontend skills suggest them).
- **Visual hierarchy:** Encode status and severity exclusively through `SeverityChip` markers, font weight, contrast inversion (black/white), and `1px` borders.
- **Geometry & typography:** Zero border radius (`rounded-none` / `radius: 0`) everywhere. Use monospace for hashes, IDs, IPs, domains, metrics, and timestamps; use sans-serif for prose and labels.

### Database & Row-Level Security (`db/` & `api/`)
- **Migrations:** Add schema changes only as `db/migrations/NNNN_name.sql` (§07). Never modify applied migrations.
- **RLS tenant isolation:** Policies key on `current_setting('harizeon.org_id', true)`.
  - App runtime **must** connect using a **non-owner** Postgres role (table owners bypass RLS and are reserved for migrations).
  - Set `SET LOCAL harizeon.org_id = '<org_id>'` inside a per-request transaction so pooled connections never leak tenant context across requests.

## 4. Agent Execution Discipline

- **Plan multi-file work (`planning-with-files`):** For any task touching 3+ files or spanning planes (`web/` + `api/` + `db/`), create or update `PLAN.md` with discrete steps before editing code, and check off items as verified.
- **Minimal code (`ponytail`):** Prefer native browser, Node/Fastify, and Python stdlib capabilities over adding dependencies. Avoid premature abstractions, wrapper factories, or speculative config flags.
- **Root-cause debugging (`superpowers`):** Trace failures to their source before patching. Never silence errors with `@ts-ignore`, `as any`, `eslint-disable`, or bare `except:` blocks.
- **Compounding memory (`napkin`):** Whenever a repo-specific gotcha, command quirk, or user correction surfaces, record a concise one-line rule in `.agents/napkin.md` (keep under 100 lines).

## 5. Security & Git Hygiene

- Never commit `.env`, API keys, tokens, or test credentials. Copy `.env.example` for local setup.
- Do **not** run `git commit` or `git push` unless explicitly instructed by the user.

## 6. Verification Gate (Run Before Declaring Done)

1. **Web typecheck & build:** `cd web && npm run build`
2. **Web lint:** `cd web && npm run lint`
3. **API & Worker tests (when touched):** Run the test suites in `api/` and `worker/` (without requiring DB credentials in `worker/`).
4. **Migrations (when `db/` touched):** Verify `docker compose up` applies new `NNNN_name.sql` cleanly against Postgres 16 and non-owner RLS isolation holds.
5. **Browser verification (when `web/` UI touched):** Inspect the running app with `playwright` MCP to confirm zero console/runtime errors, strict black-and-white styling, and `0px` border radius.
